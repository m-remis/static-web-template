# Internationalization (i18n)

> Part of the agent docs. Router: `AGENTS.md`.

## Internationalization (i18n) - runtime language switch

Language is a **runtime switch backed by `localStorage`**, not separate URLs and
not a build step. It internationalizes two layers, kept apart on purpose:

- **Content** - one full spec file per locale: `LOCALE_SPECS` in the I18N block
  near the top of `engine.js` maps each locale to its file (`en` →
  `site-spec.json`, `sk` → `site-spec.sk.json`). Each file is a **complete,
  self-contained spec** - not a base + overlay. This is a deliberate exception
  to DRY: it's the one place you could re-add a merge, and we don't (the engine
  removed `deepMerge` for a reason). Locale-invariant data (contact, images) is
  duplicated across files; `launch-check`'s `checkLocales()` warns if the
  section set drifts between them.
- **Chrome** - the strings the spec never carries (aria-labels, the error
  screen, weekday names, the switcher) live in the `UI` table in `engine.js`,
  keyed by locale with an English fallback. Read them with **`t("key")`** - never
  hardcode a user-facing string in a builder again; add it to `UI` (both
  locales) and call `t()`.

Flow: `init()` calls `resolveLocale()` (reads `LANG_KEY` from `localStorage`,
falls back to `DEFAULT_LOCALE`) **before** fetching, so the right spec loads and
every `t()` reads the right locale. `renderHead()` sets `<html lang>` from the
loaded `meta.lang`. The header `#langSwitcher` container **ships `hidden`**;
`initLang()` builds a custom **`<details>` dropdown** into it and reveals it
*only* when a second locale exists (so a single-locale site shows no switcher at
all, even before/without JS - the `.lang-switcher[hidden]` CSS rule keeps the
container hidden until then). The summary is the frosted "button" showing the
active locale's **ISO 639-1 code** (`EN`, `SK`); the panel lists one option per
locale (each shows the code, with the endonym from `LOCALE_NAMES` as the
accessible label/tooltip). Picking a locale hands off to **`switchLocale()`**,
which saves the choice and **re-renders in place** - no page reload. The
dropdown closes on Escape (focus returns to the summary) and on outside click.
`applyChromeStrings()` pushes localized aria/text onto the static shell elements
`index.html` ships in English.

**The switch does not reload the page, and it is instant.** `switchLocale()`
awaits the new spec (normally already cached), calls `teardownSite()` and
re-runs `renderSite()`. The background, theme, header chrome, current tab and
scroll position all survive; the copy simply changes, in one frame, with no
fade and no CSS involved. Two things make that a single-frame swap rather than
a flash of empty content - keep both:

- **The network is off the critical path.** Specs are a few KB, so a fetch is
  pure latency - and `_headers` serves them `max-age=0, must-revalidate`, so
  even a warm HTTP cache still pays a round-trip for a `304`. `SPEC_CACHE`
  keeps parsed specs for the session (switching back is free), and `initLang()`
  calls `warmLocale()` for every other locale at **load + idle**
  (`whenLoadedAndIdle`), with hover / `toggle` on the dropdown as a backstop
  for a click that beats the idle callback. Idle and not intent alone: a touch
  user can open the dropdown and tap an option faster than a round-trip. On a
  cold miss the old copy just stays up until the spec lands - nothing is
  blanked while waiting.
- **Teardown and render share a frame.** With the spec in hand, the only awaits
  between `teardownSite()` and the end of `renderSite()` are on settled
  promises - microtasks - so the browser never paints the torn-down state.
  **Don't add a `setTimeout` / `requestAnimationFrame` wait in that path**, or
  an empty `#main` becomes visible.

**It cannot get stuck.** The swap runs inside `try / catch / finally`: if the
render throws, the page falls back to the same error screen a broken spec gets
(after a fresh `teardownSite()`, so no dead controls are left), and the
`localeSwapping` lock is always released.

Two earlier designs, so nobody re-tries them: `location.reload()` blinked the
whole page (empty shell, background restart, lost scroll position), and a
crossfade of `#main` (`html.site-swapping`) added dead time - the new text
could not appear until the fade-out finished. If a build ever wants a softer
swap, fade the new content **in** only, never out.

See "Re-rendering in place" in `docs/engine-internals.md` for the rule this
puts on every `init*` function.

**Trade-off (know this):** because the switch is runtime-only, the **static SEO
mirror reflects the default locale** - `generate-static.mjs` and `launch-check`
run on `site-spec.json` (English). Crawlers see English; alternate locales are
for visitors, not search engines. That's the accepted cost of a switcher over
per-locale URLs. To fully validate a locale's content, run
`node launch-check.js --site-spec site-spec.sk.json`.

**To add a language:** add its spec file, add a `LOCALE_SPECS` entry, add a
`LOCALE_NAMES` endonym, add a `UI` block for it, and translate the weekday
`days` array. The dropdown lists every locale, so any number works - no per-
locale switcher code to touch. Also mirror the strings in `404.html`'s inline
script (it localizes from the same `localStorage` key without loading the engine),
and add a cache rule for the new spec file in `_headers` next to the existing
`/site-spec.sk.json` one.
